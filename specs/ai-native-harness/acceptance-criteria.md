# Acceptance criteria

Each item is a checkable, observable statement. If it isn't testable, rewrite it.

- [x] AC-1: Given a new Claude Code session in the repo, when it starts, then the always-on project context (`CLAUDE.md`, its `@` imports, and rules without `paths`) is ≤ 5,120 bytes, as reported by `scripts/sync-agent-harness.ps1`.
  - Evidence: `Get-HarnessContextReport` (printed by `scripts/sync-agent-harness.ps1`) → `AlwaysOnBytes : 3656` (was 12,730; measured on an LF checkout, since CRLF adds about 2 %). Pester: `counts always-on bytes and skill kinds`, `flags always-on total over budget via imports`.
- [x] AC-2: Given the project skills, when a session starts, then at most 6 skills expose a description to the model, and the 5 human-run workflows (`implement-ticket`, `analyze-requirement`, `onboarding`, `update-docs`, `fix-warnings`) are slash-invocable with `disable-model-invocation: true`.
  - Evidence: `ModelSkillCount : 5`, `UserSkillCount : 5`. `grep -l 'disable-model-invocation: true' .claude/skills/*/SKILL.md` lists exactly the 5 workflows. This session's skill listing shows only the 5 model-invocable project skills. Pester: `flags more than six model-invocable skills`.
- [ ] AC-3: Given an agent edits a file matching a rule's `paths`, when the agent reads that file, then Claude Code loads the rule from `.claude/rules/`, and Copilot receives the same text from `.github/instructions/` with an `applyTo` equal to the rule's globs.
  - Evidence: in this session, reading `specs/ai-native-harness/acceptance-criteria.md` loaded `.claude/rules/specs.md` automatically. `.github/instructions/specs.instructions.md` has `applyTo: "specs/**/*.md"`, equal to the rule's `paths`, and `frontend.instructions.md` joins both globs. Pester: `maps paths to applyTo and keeps the body`, `mirrors nested rules and agents`. Pending: Copilot applying the file is observed only in the AC-12 hand-check.
- [ ] AC-4: Given a change to `.claude/rules/` or `.claude/agents/` that is not followed by a sync, when CI runs, then the harness job fails with a drift finding. CRLF-only differences never count as drift.
  - Evidence: appending a line to `.github/instructions/docs.instructions.md`, then `-Check` → `[Drift] … changed` / `harness check: 1 finding(s)`, exit 1. This needed fix 48d5151: before it, a lone finding printed OK and exited 0 on Windows PowerShell. The `harness` job in `.github/workflows/build.yml` runs `-Check`. Pester: `flags drift`, `ignores CRLF line endings in the committed mirror`, `exits 1 when the lint has exactly one finding`. Pending: the CI job itself hasn't run yet (branch not pushed); tick it after the first `harness` run on GitHub fails on a drift or passes clean.
- [x] AC-5: Given the harness files (`AGENTS.md`, `CLAUDE.md`, `.claude/**`, `.agent/README.md`, `.agent/tools/`, `.agent/memory/`) and `specs/`, when `-Check` runs, then every backticked repo path in the harness files resolves, every relative markdown link in the harness files and `specs/` resolves, and no term from the staleness list appears in the harness files.
  - Evidence: `-Check` → `harness check: OK`. Pester: `flags a missing backticked path`, `flags a broken relative markdown link in specs`, `resolves anchored and root links and ignores code, placeholders and URLs`, `flags stale terms`, `does not flag pnpm install as npm install`.
- [x] AC-6: Given harness content that names a code symbol or package in backticks, when `-Check` runs, then it fails unless the name appears in the source corpus (`src/`, `tests/`, solution and package manifests) or is on `scripts/harness/facts-allowlist.txt` with a reason.
  - Evidence: `-Check` → OK, after the Facts lint caught and fixed `Coupon.API`, MediatR APIs, `IRepository`, RTK and MUI claims. Pester: `accepts symbols, generics, calls and packages found in the corpus`, `flags a symbol that exists only in node_modules`, `honours the allowlist`, `flags an allowlist entry without a reason`.
- [x] AC-7: Given a folder under `specs/` other than `_template`, when `-Check` runs, then it fails unless `spec.md` has a valid `**Status:**`, `acceptance-criteria.md` has at least one uniquely numbered `AC-n`, and `test-plan.md` maps exactly the defined AC ids.
  - Evidence: `-Check -Category Specs` → OK on `specs/ai-native-harness/`. Pester: `accepts a complete spec`, `flags an invalid status`, `flags duplicate AC ids`, `flags an AC missing from the test plan`, `flags an undefined AC in the test plan`, `flags a missing spec file`.

## Non-functional
- [ ] Portability: every script and module runs unchanged on Windows PowerShell 5.1 and on PowerShell 7 on Linux.
  - Pending: Windows PowerShell 5.1 is verified (Pester 79/79 locally; `-Check` OK). PowerShell 7 on Linux runs only in the CI `harness` job, which hasn't run (branch not pushed).
- [x] Performance: `sync-agent-harness.ps1 -Check`, including Facts, finishes in ≤ 60 s on the dev machine.
  - Evidence: `Measure-Command { … -Check }` → `1.68` s.
- [x] Safety: sync writes only `.github/instructions/` and `.github/agents/`. The eval runner never modifies the main working tree and removes its worktrees even on failure.
  - Evidence: Pester `leaves .github/workflows untouched`, `removes mirror files whose source is gone`, `leaves the main working tree clean and removes the worktree`, `removes the worktree when the invoker throws`, `hides tests/skill-evals from the session without dirtying git status`. After 36 real sessions the main tree was unchanged and no eval worktree was left.
- [x] Cost: no `claude` invocation runs in CI. `eval-skills.ps1 -DryRun` lists every planned invocation without running any.
  - Evidence: `grep -n -i claude .github/workflows/*.yml` has no matches (exit 1). Pester: `lists every planned run and invokes nothing`.
